### 271 — Dependabot #5, #7, #8 after v0.2.0: mypy 2.4.1, ruff 0.17.3, platformdirs 4.14.0 (DEP-1)

**Method.** As §248: one `upstream-reader` per PR, then one worker
landing all three as local commits on `main` (`534057f`), not GitHub
merges. Each PR's base, `5da3150`, was 168 commits behind, and only
`check` and `audit` had run on it, never `check-intel` or
`check-windows`. Each commit carries `pyproject.toml` and `uv.lock`
together. The lock diffs equal the PRs' except one line: each PR
also moved `revision = 3` to `5`, drift from its old base, since
`main` is already at revision 5.

**Landed.**
- **#5 mypy 2.4.0 → 2.4.1** (`0c7d86c`, dev only). A patch for a
  2.4.0 regression (upstream PR 22231): mypy skipped a property
  getter's body when the setter assigned to `self`, and the stricter
  check can newly report errors, `unused type: ignore` among them.
  Seeker's one settable property, `DashboardPage.selected_playlist`,
  has a setter that calls a method and never assigns to `self`. Both
  `--strict` runs, native and `--platform win32`: no issues in 149
  files.
- **#7 ruff 0.16.10 → 0.17.3** (`03946bb`, dev; `>=0.17.3,<0.18`).
  0.17.0's breaking changes do not reach this config:
  `requires-python` sets the target, `select` is explicit, and ICN is
  not selected. By `--show-settings`, this config enables 456 rules
  against 455. The one addition is RUF071 (`os-path-commonprefix`,
  now stable, through "RUF"). E301–E306 are still preview and still
  selected by exact code, so CLAUDE.md's "E30 selects none" holds.
  `--select RUF100 --diff` still strips a `# noqa: F401`, so its
  RUF100 warning holds too. The changed E501 length rule (a trailing
  pragma no longer counts) left no `noqa` stale. No new findings
  under `--no-cache`, and no source change.
- **#8 platformdirs 4.12.3 → 4.14.0** (`8223c25`, runtime). Read in
  both wheels' source for Seeker's three calls, `user_data_dir`,
  `user_log_dir` and `user_cache_dir("Seeker", appauthor=False)`.
  - macOS: the same `~/Library/{Application Support,Logs,Caches}/Seeker`
    under both versions (printed here). New: `_xdg.py::_expand_user`
    treats a *relative* `HOME` as unset and takes the home from the
    password database, and raises if the result is not absolute. It
    is used only by `user_projects_dir`, which Seeker does not call,
    and every test sets `HOME` to `str(tmp_path)`.
  - Windows: the same `LOCAL_APPDATA` folders. `get_win_folder` still
    reads `WIN_PD_OVERRIDE_<CSIDL>` first (`windows.py:402-411`), and
    R14-S2's isolation fixture relies on that. But it now ignores an
    override that is not fully qualified: `_is_fully_qualified` turns
    `/` into `\` and rejects a UNC path missing its server or share,
    so a bare `\\server` is dropped. A pytest tmp path, `C:\…`, still
    qualifies. This was run as the `Windows` class on macOS, not
    observed on Windows.
  - The new imports are stdlib (`stat`, `pwd`, `pathlib`) or internal,
    so `seeker.spec` needs nothing. The package is MIT with no
    `Requires-Dist`, so `help_text.py`'s notice stands.
  - **A plain `uv lock` after the constraint edit takes 4.14.4**,
    which nobody has read. 4.14.0 was locked with `uv lock
    --upgrade-package platformdirs==4.14.0`, under the constraint
    `>=4.14.0`. On the committed tree a plain `uv lock` keeps 4.14.0
    (byte-identical); only `--upgrade-package` moves it. 4.14.1–4.14.3
    are Pyodide and XDG fixes; 4.14.4 needs its own PR and its own
    read.

`tests/CLAUDE.md`'s Windows `HOME` fact now cites "platformdirs
